# Сайт Мухомора

Статический сайт Mukhomor для Windows, Linux и Android. Публикация выполняется после явного одобрения владельца. Предпросмотр и проверки сами по себе ничего не отправляют на GitHub.

Статический сайт без npm-зависимостей; HTML и снимки данных подготавливают скрипты Node.js. Публичные файлы находятся только в `public/`: главная, документация, история обновлений, релизы, правила использования, FAQ, страница данных, CSS, JavaScript, фирменная графика, шрифты и их лицензии. Относительные ссылки работают и в корне домена, и под `/Mukhomor/` на GitHub Pages. Шрифты и графика локальные. Необязательная аналитика выключена до настройки; когда она включена, Turnstile и сбор событий запускаются только после согласия посетителя.

Первый экран занимает высоту окна. Его фон основан на алгоритме `native/visual_build.rs`, гриб — на оригинальной сетке приложения. Кнопка «Читать далее» запускает пиксельный переход к информации; обычная прокрутка также доступна. Tiny5 используется для заголовков, бренда и управления, Monocraft — для чтения, команд и технических подписей. Роли и размеры задаёт `public/typography.css`; источники и условия коммерческого использования указаны в [FONTS.md](FONTS.md). Управление анимацией есть на первом экране и в подвале; учитывается системная настройка уменьшения движения. За пределами экрана и в фоновой вкладке отрисовка приостанавливается.

## Просмотр и проверка

Из корня репозитория (нужен Node.js 18 или новее):

```sh
node website/scripts/serve.mjs
```

Открыть `http://127.0.0.1:4173/Mukhomor/`. Для другого порта задать переменную `PORT`. Сервер слушает только loopback и выдаёт только `public/`.

```sh
node website/scripts/check.mjs
```

Проверка охватывает локальные ссылки, якоря, ресурсы, метаданные, названия и ограничения текстов, синтаксис JavaScript. Визуальную проверку выполнять отдельно в браузере на узком и широком экране; проверить вкладки сценариев, просмотр интерфейса, разделы документации, историю навигации и клавиатуру.

Сайт можно открыть и через `public/index.html` без сервера. В таком режиме браузер может не предоставлять копирование в буфер обмена; команда остаётся доступной для ручного копирования. Без JavaScript документация показывается целиком, основные ссылки и инструкции доступны.

## История обновлений

`public/changelog.html` — статическая страница, доступная также без JavaScript.
В `changelog.json` хранится `unreleased` — ещё не выпущенное. Опубликованные
версии берутся из `content.json` и актуализируются через панель сайта. Даты берутся из
`published_at` и отображаются по Москве. Текущая версия исходников и локальные
теги сами по себе не подтверждают публикацию.

После правки заметок выполните `node website/scripts/content.mjs`,
`node website/scripts/changelog.mjs`,
`node website/scripts/seo.mjs`, затем
`node website/scripts/check.mjs`. Последняя команда также проверяет, что HTML
синхронизирован с JSON. Правило поддержки истории закреплено в `../AGENTS.md`.

## Фирменные ресурсы

`assets/mushroom-art.json` хранит утверждённый рисунок 80×72 и мини-версии 16×16, 24×24 и 32×32. Маски материалов отделены от тональных пикселей: цвета следуют всем темам приложения. `generate-artwork.mjs` создаёт `native/src/mushroom_data.rs`, а `export-assets.mjs` — SVG сайта, favicon, иконку Linux и ресурсы Android. Он также копирует Tiny5, лицензию и демонстрационный скриншот. Выполнять при изменении фирменных ресурсов, а не при каждом просмотре:

```sh
node website/scripts/generate-artwork.mjs
node website/scripts/export-assets.mjs
node website/scripts/export-scene.mjs
node website/scripts/export-gutters.mjs
node --test --test-isolation=none website/scripts/artwork.test.mjs
```

`export-scene.mjs` заранее рассчитывает 24 кадра пиксельного поля и переносит цветовые оттенки большого гриба. Браузер интерполирует готовые кадры на небольшом canvas с частотой до 20 кадров в секунду; расчёт шума на каждом кадре не требуется. `scene.css` задаёт полноэкранную композицию и единое пиксельное оформление, `scene.js` — фон, мицелий, переход и появление секций. Оригинальная маска мицелия с 48-й строки и расстояния распространения сохранены; регрессионные проверки находятся в `native/src/hero_motion.rs`. Команда `node website/scripts/generate-artwork.mjs --check` проверяет актуальность нативных данных без перезаписи.

Виньетка первого экрана отрисовывается один раз на сетке 144 × 96 и обновляется только при изменении размера сцены. Расчёт учитывает обрезку `object-fit: cover`, поэтому затемнение остаётся у реальных краёв экрана в любой ориентации. Нижний край полностью совпадает с `--bg`; текст, навигация и главный гриб остаются поверх затемнения. Центральный гриб увеличен на 15% относительно прежнего размера с сохранением центра; на низких окнах для мицелия предусмотрен отступ от подписи.

Боковой декор — два повторяемых SVG-фона размером 280 × 1440 px, созданные из сетки MINI командой `node website/scripts/export-gutters.mjs`. Координаты и размеры грибов постоянны; рост содержимого открывает следующие повторы, а не перераспределяет рисунок. Генератор также записывает границы фигур в блок `gutter-tiles` файла `scene.css`: `site.js` скрывает незавершённый нижний гриб при изменении высоты, не сдвигая остальные. Панели абсолютно позиционированы относительно содержимого, без привязки к viewport и обработчиков прокрутки. При ширине менее 1360 px декор скрыт; на широких экранах обрезается строго по свободным боковым полям. Приглушённые розовый и teal меняются местами на пятнах.

Тексты основаны на документации и возможностях исходников приложения. Опубликованный архив может отставать от текущей ветки: перед публикацией сайта нужно сверить описанные возможности с предназначенным для пользователей релизом. На сайте протокол называется **Mycelia**. Примеры URI этого экспериментального протокола намеренно не публикуются, поскольку изменение публичного названия не переименовывает схему импорта в существующих сборках.

## Публикация GitHub Pages

После разрешения владельца сайт публикует `.github/workflows/pages.yml`: при изменении `website/**` в `main` или при ручном запуске. В Settings → Pages используется GitHub Actions.

Перед push выполните генераторы content, changelog и seo, затем `node website/scripts/check.mjs`. Проверьте список Git-файлов и `tests/Test-PublicSource.ps1`. Workflow загружает только `website/public`; исходники панели, базы, конфигурация VPS и рабочие профили в Pages не попадают. Историю старых релизов сохраняйте.

`pages-workflow.yml.example` — справочный шаблон; рабочая конфигурация находится в `.github/workflows/pages.yml`.

## Индексация и ответы поисковых систем

Канонический адрес: `https://mukhomo.github.io/Mukhomor/`. Общие данные находятся
в `site.json`, фактические вопросы и ответы — в `faq.json`. После их изменения
выполнять `node website/scripts/seo.mjs`, затем `node website/scripts/check.mjs`.
Генератор обновляет canonical, Open Graph/Twitter, CSP, Schema.org, sitemap,
robots, llms и публичную конфигурацию аналитики. Версия приложения берётся из
подтверждённых releases в `changelog.json`, не из локального Cargo.

Сущности SoftwareApplication, SoftwareSourceCode, WebSite, TechArticle и FAQPage
связаны постоянными `@id`. FAQ в HTML и JSON-LD строится из одного источника;
контент доступен без JavaScript. Не добавлять придуманные рейтинги, отзывы,
результаты тестов или неподтверждённые возможности. `llms.txt` — дополнительное
текстовое представление, не обязательный стандарт или гарантия попадания в ответы.
По [документации Google](https://developers.google.com/search/docs/appearance/ai-features)
для AI-поиска действуют обычные требования к индексируемому полезному контенту;
специальной обязательной AI-разметки нет. FAQPage не обещает rich result Google.

После одобренной публикации:

1. Проверить доступность всех пяти canonical-страниц, sitemap, изображения превью
   и структурированных данных по HTTPS без авторизации.
2. Добавить URL-prefix property `https://mukhomo.github.io/Mukhomor/` в Google
   Search Console, подтвердить владение и отправить `sitemap.xml`. Аналогично
   настроить Bing Webmaster Tools. Не подставлять выдуманные verification tokens.
3. `robots.txt` действует **только в корне хоста**. Файл `/Mukhomor/robots.txt`
   поисковые роботы не используют как основной. Подготовлен `domain-root/robots.txt`
   для отдельного репозитория `0nionow1.github.io`; после отдельного одобрения
   объединить его с уже существующими правилами и опубликовать в корне. Не заменять
   чужие правила вслепую. Отсутствие robots.txt не запрещает индексацию проекта.
4. Проверить, что корневые правила не запрещают Googlebot, Bingbot,
   OAI-SearchBot, PerplexityBot, Claude-SearchBot. Допуск поискового робота и
   разрешение обучения моделей — разные настройки; текущий шаблон открыт всем.
5. Ссылаться на сайт из GitHub About/README после согласования, поддерживать
   актуальность документации и опубликованных релизов. Индексация и цитирование
   зависят от поисковой системы, не гарантируются разметкой.

Корневой robots: [правила Google](https://developers.google.com/search/docs/crawling-indexing/robots/intro).
Роботы: [OpenAI](https://developers.openai.com/api/docs/bots),
[Perplexity](https://docs.perplexity.ai/docs/resources/perplexity-crawlers),
[Anthropic](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler).

## Аналитика

Бэкенд, определения метрик, ограничения защиты, примеры Nginx/systemd,
HTTPS по IP и будущий Cloudflare Tunnel описаны в [analytics/README.md](analytics/README.md).
Он не входит в Pages. `site.json` принимает только публичный endpoint и site key;
секреты Turnstile и подписи токенов хранятся отдельно на VPS. На `privacy.html`
посетитель может отключить сбор. Для разработки и локальных предпросмотров он выключен.

Закрытая панель владельца доступна на `/admin/` HTTPS-адреса бэкенда после установки
и настройки приватного входа. В ней сводка, дни и страны; HTML/JS панели находятся
в отдельном бэкенде. После пароля нужен одноразовый код из личного чата Telegram;
отправка выполняется коротким API-запросом, отдельный бот-процесс не нужен. Файлы панели —
в `analytics/admin/`, не в публичной сборке. Порядок настройки и восстановления
доступа описан в [инструкции бэкенда](analytics/README.md#закрытая-панель-владельца).

## Релизы, тексты и правила

Все основные кнопки «Скачать» открывают `releases.html`. На ней рекомендуются
последняя по номеру Stable или выбранная владельцем видимая Stable. Версии «В проверке»
тоже можно скачать; они не рекомендуются автоматически. Файлы ведут только в Releases
репозитория проекта. Импорт номера версии не создаёт и не публикует GitHub Release.

Панель VPS: «Релизы» → номер уже опубликованной версии → «Добавить с GitHub» → описание
и статус → «Сохранить черновик» → «Предпросмотр» → «Опубликовать». В «Тексты сайта»
редактируются главная, документация, FAQ, правила и сведения о данных без HTML.
Публикация применяет все сохранённые правки вместе; история позволяет восстановить
прежнюю публикацию в черновик. Первое развёртывание создаёт только черновик.

`site.json: content` задаёт публичный HTTPS endpoint. Сайт получает `GET /v1/site`
без cookie и без регистрации событий; аналитика включается отдельно и по согласию.
Сетевой запрос раскрывает VPS обычный IP подключения, но API содержимого не записывает
его в статистику. На localhost используется локальный снимок. При недоступном API
показывается уведомление и остаются рабочими ссылки из проверенного статического снимка. Статическая копия доступна без JavaScript и может отставать от панели. Файлы всех видимых версий идут от новых к старым; рекомендация Stable обозначается отдельно.

Для индексаторов, которые не выполняют JavaScript, обновляйте статический снимок:

```sh
node website/scripts/content.mjs --snapshot /path/to/mukhomor-content.json
node website/scripts/changelog.mjs
node website/scripts/seo.mjs
node website/scripts/check.mjs
```

JSON скачивается в панели из «История и резервная копия». Команды не публикуют сайт.
GitHub Pages остаётся статическим хостингом: живые правки панели сами по себе не меняют
HTML в репозитории, robots, sitemap и llms.txt. Публикуйте обновлённый снимок только
с разрешения владельца.

`policy.html` — проект правил, а не заключение о законности сервиса. В нём раздельно
описаны действия пользователя, собственный VPS, лицензия MIT и допустимые ограничения
ответственности. Абсолютное освобождение от ответственности и юридически достаточное
принятие правил всеми пользователями не гарантируются: страницу могут не посещать
пользователи прямых загрузок с GitHub. Перед запуском юристу нужно проверить применимое
право, фактическую модель проекта, идентификацию владельца и способ принятия условий.
Указание бренда и GitHub Issues не заменяет обязательные реквизиты, если они требуются.
Основание оговорки о неустранимой ответственности: [статья 401(4) ГК РФ](https://www.consultant.ru/document/cons_doc_LAW_5142/94ebfa384dd37d9377ee7b78ab23c150ff69e5b4/).

## Cookies и согласие

Политика cookies и локального хранения находится в public/privacy.html. Аналитика по-прежнему выключена в site.json. После её включения и до явного согласия не загружаются Turnstile и аналитические запросы. Отклонение и согласие имеют одинаковое оформление; закрытие панели не даёт согласия. Выбор хранится 180 дней с датой и версией уведомления. Это выбранный срок проекта, а не единый обязательный срок для всей Европы.

Настройки доступны в подвале каждой страницы; при согласии рядом доступен отзыв одним нажатием. Отказ удаляет локальные токены, отменяет текущие запросы и применяется в других вкладках. Запрос, уже принятый сервером, нельзя отозвать задним числом. Старые либо истёкшие согласия не включают сбор. DNT/GPC имеет приоритет. Даты истечения localStorage проверяются кодом; браузер не удаляет такие записи сам.

При изменении целей, поставщиков или существенных условий обновляйте NOTICE в public/analytics.js и редакцию политики, чтобы запросить новое согласие. Сохраняйте историю опубликованного уведомления и конфигурации согласия. Локальная запись выбора сама по себе не доказывает полное соблюдение GDPR. Не добавляйте больше персональных данных только ради журналирования согласия.

Эта реализация не является юридическим заключением о соответствии GDPR/ePrivacy. До запуска сбора для аудитории ЕС следует уточнить фактического ответственного за обработку и конфиденциальный контакт, основания технической обработки, поставщика и расположение VPS, применимые соглашения с поставщиками и условия международной передачи. Пока известны бренд «Мухомор» и публичные GitHub Issues; реквизиты и частный канал для запросов не подтверждены. Не объявляйте аналитику анонимной либо автоматически освобождённой от согласия только из-за отсутствия HTTP cookies.

Владелец выбрал сохранять личные сведения команды непубличными. Сбор остаётся выключенным. Это не скрывает публичный адрес VPS, используемый API содержимого, и аккаунт GitHub, на который ссылается сайт. Режим статического снимка без обращения к VPS требует отдельного решения, поскольку меняет способ применения правок из админки; пока сохранено существующее живое обновление каталога.

Источники: [CNIL: cookies и другие средства отслеживания](https://www.cnil.fr/fr/cookies-et-autres-traceurs/que-dit-la-loi), [CNIL: согласие и отказ](https://cnil.fr/fr/cookies-et-autres-traceurs/regles/cookies/comment-mettre-mon-site-web-en-conformite), [EDPB: область статьи 5(3)](https://www.edpb.europa.eu/our-work-tools/our-documents/guidelines/guidelines-22023-technical-scope-art-53-eprivacy-directive_en), [Cloudflare Turnstile](https://www.cloudflare.com/turnstile-privacy-policy/).

## Переходы между страницами

`public/navigation.js` загружается синхронно в начале `<head>` всех страниц,
до внешних CSS. Небольшой встроенный стиль перед ним задаёт фон документа,
закрывающий слой и размеры canvas; общий блок формирует `scripts/seo.mjs`.
Он использует ту же пиксельную волну для «О приложении» и внутренних ссылок.
Закрывающая половина (575 мс) заканчивается сплошным кадром `#120c18`;
после настоящей загрузки HTML открывающая половина продолжает рисунок.
Ранний CSS-слой закрывает новый документ до первого отображения контента.
На `pagehide` уходящий кадр замораживается вместе со слоем, чтобы браузер
не показывал старое содержимое при смене документа. Перед раскрытием canvas
остаётся полностью закрашенным в течение кадра; два requestAnimationFrame
дают браузеру применить вёрстку, якорь и подготовить слой отрисовки.

Одноразовая запись `mukhomor.navigation` в sessionStorage содержит только
целевой путь и время, действует 15 секунд и сразу удаляется при чтении.
Её назначение описано в политике локального хранения. При недоступном хранилище,
canvas или отключённой анимации остаются обычные ссылки. Модифицированные клики,
внешние ссылки, скачивание файлов и вкладки документации сохраняют поведение браузера.
Reload, прямой вход и история не повторяют старый переход; BFCache очищает слой.
Шрифты ожидаются до 1800 мс. Разбор документа и отменённая навигация имеют
страховочный предел 8 секунд; даже при остановленном rAF сайт не остаётся закрытым.

Проверка навигации: `node --test --test-isolation=none website/scripts/navigation.test.mjs`.

## Скриншоты, инфографика и интервалы

`public/visuals.css` подключается после общих стилей на всех публичных страницах: задаёт
общие интервалы между разделами, галерею и иллюстрации руководства. На широком
экране основные разделы разделяет адаптивный отступ до 128 px, на телефоне —
80 px. Рамки используют существующие SVG мицелия. Схемы состоят из доступного
HTML-текста и собственных пиксельных пиктограмм; внешних изображений нет.

Главная показывает четыре экрана с ручным переключением. `public/visuals.js`
поддерживает стрелки клавиатуры, Home/End и увеличение снимков в диалоге.
Escape закрывает просмотр, фокус возвращается к исходному изображению.
Без JavaScript первый экран и все снимки в руководстве остаются видимыми,
ссылки открывают PNG напрямую. Изображения имеют размеры и загружаются лениво.

Для обновления оригинальных снимков из актуального Slint-интерфейса:

```sh
node website/scripts/export-screenshots.mjs
node website/scripts/check.mjs
```

Главная дополнительно использует `public/experience.css`. Общие `roots.css` и
`experience.js` рисуют мицелий на главной и страницах с боковым орнаментом.
Композиция чередует крупный экран, спокойный текст и схему. На первом экране
остаётся один главный гриб. На экранах шире 1100 px одновременно растут до трёх
случайных ветвей из разных кончиков его корней. Рисунок повторяет устройство корней
логотипа и разделителей: сетка и толщина 4 px, ступенчатые изгибы и развилки
второго и третьего порядка. Светлые и тёмные ветви
сохраняют глубину рисунка; цвет переходит от исходного корня к розовой рамке.
Точки старта определяются по геометрии настоящего пиксельного гриба. Область поиска
занимает всю главную страницу: фиксированного маршрута справа и обязательного
перехода к галерее больше нет. Текст, кнопки, изображения и инфографика защищены
прямоугольными зонами с отступами; `data-root-avoid` позволяет добавить свою зону.
Для текста учитывается его фактическая ширина, чтобы пустые поля оставались свободными.
Каждый шаг проверяется до отрисовки. Направление меняется короткими ступенями;
проверка пространства впереди помогает заранее обходить препятствия. Учёт занятых
участков ограничивает пересечения. Четыре авторских мотива создают крючки,
возвратные изгибы и мелкие развилки; углы слегка срезаны, сохраняя пиксельный рисунок.
`scene.js` сообщает фактическое завершение роста корней через `mukhomor-roots-ready`;
`experience.js` дополнительно ждёт завершения появления главного гриба. Боковой
орнамент работает независимо, в том числе при открытии страницы сразу по якорю. Скрытой
подложки у пути нет: ветви открываются только после достижения их развилок.
Точки поиска учитывают текущую область чтения. Исчерпавшая путь ветвь затухает,
а новая начинает расти из другого свободного кончика. Одновременно существуют
максимум семь растущих корней и четырнадцать групп вместе с затухающими;
длина каждого корня ограничена 100 шагами роста.
Боковые отростки появляются по всей длине: завершённые детали объединяются
в три статических SVG-контура по стилю, а покадрово обновляются только растущие.
При удалении корня освобождаются все его узлы и занятые ячейки.
Отрисовка обновляется не чаще 20 раз в секунду и останавливается
вне страницы, в скрытой вкладке, при ручной паузе и `prefers-reduced-motion`.
Пауза сохраняет текущий рисунок; возобновление не повторяет появление гриба.
При первом открытии с отключённой анимацией показывается статический рисунок.
На узких экранах мицелий скрыт.

Среди боковых грибов активен примерно один из двенадцати. Случайный выбор делается
при открытии страницы и сохраняется при прокрутке; участвуют все размеры исходного
орнамента. Крупные грибы остаются обрезаны границей бокового поля точно как фон.
Цветной слой приглушён до 24% у крупных и 34% у остальных грибов. Из ножки выходят
одна или две ветви с непрозрачностью 42% и скоростью 35 px/с вместо 100 px/с у главного
гриба. Мятный цвет постепенно переходит в розовый по мере удаления от ножки.
Координаты берутся из `--gutter-sources`, который генерирует `export-gutters.mjs`
вместе с SVG-орнаментом. Весь эффект использует один цикл анимации и общую карту
занятых клеток; повторные проверки клеток кешируются на время выбора очередного шага.
За пределами видимой области рост приостанавливается, далёкие ветви удаляются вместе
с занятыми клетками, а готовые развилки сохраняются в статических контурах.
Сохранённая ручная пауза действует и на внутренних страницах.

В галерее доступны реальные темы «Неон», «Поп-арт» и «Киберпанк» для всех четырёх
экранов. Темы оформлены как текстовые вкладки раздела маршрутов, с корневым
подчёркиванием выбранной темы. Они меняются нативными radio-кнопками; стрелки, Home/End переключают
экраны. Изображение сначала загружается и декодируется, затем заменяет предыдущее.
Быстрые нажатия сохраняют последний выбор; ошибка или таймаут 10 секунд сохраняют
рабочий снимок и показывают сообщение. Тема действует только на демонстрацию.
Диалог открывает именно текущий снимок. Короткие отклики кнопок и ветви вкладок
работают только при взаимодействии. Все новые эффекты учитывают общую настройку
анимации и `prefers-reduced-motion`, включая смену предпочтения во время работы.

Нужны Rust и уже загруженные зависимости UI: команда использует `--offline`.
Рендер запускает только изолированный `ui/src/preview.rs` с демонстрационными
профилями, без VPN-контроллера и пользовательских конфигураций. Временные снимки
попадают в `target/website-screenshots/`; 14 явно перечисленных кадров —
в `public/assets/screenshots/`. `manifest.json` записывает имя fixture, размеры
и SHA-256. Разрешённые публичные файлы перечислены поимённо в `.gitignore`.
Проверяйте снимки после изменения интерфейса и подписывайте демонстрационные данные.

Общий футер всех страниц генерируется функцией `renderFooter` в `scripts/seo.mjs`: логотип, две группы навигации, правила и настройки. Меняйте структуру в генераторе, а оформление — в `public/scene.css`; сохраняйте `data-analytics-settings`, `data-analytics-revoke` и поля `data-cms` в подписи.

Пиксельные рамки и разделители задаются в `public/pixel-frames.css`. SVG генерируются командой `node website/scripts/export-frames.mjs`: ступенчатые корни повторяют характер мицелия главного гриба. Основные и компактные варианты сохраняют сетку 4 px; края повторяются через CSS border-image и не растягиваются вдоль всей панели. Разделители используют плитки 320×48 px и 320×16 px. Статические ветви приглушённые розовые. Главные кнопки сохраняют тёмную поверхность и светлый текст при наведении, фокусе и нажатии. По корням рамки проходит teal-импульс с периодом 2,4 секунды, только пока кнопка активна: прозрачный `pixel-frame-pulse-compact.svg` повторяет её геометрию, а вращающаяся маска открывает короткий участок. При отключённой анимации участок остаётся статичным; недоступные кнопки не пульсируют. Автоматический импульс раз в 14 секунд оставлен только у условия собственного VPS и рекомендованного релиза; маска повторяет корни, а у релиза — точный рисунок верхнего края рамки. Импульсы учитывают reduced motion и общую кнопку анимации. Анимация появления использует backwards: после её завершения clip-path снимается, выступающие корни и фокус клавиатуры не обрезаются.
