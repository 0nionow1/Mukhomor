# Производительность

Основной интерфейс Mukhomor использует Rust и Slint с программной отрисовкой. Контроллер Windows и сетевое ядро работают отдельно. Замеры старого GDI-интерфейса удалены из актуальных материалов: они не характеризуют Slint.

## Что измерять

- Холодный запуск окна и время до подтверждённого состояния контроллера.
- CPU и память отдельно для интерфейса, контроллера и ядра.
- Простой с открытым окном, работа анимации, сворачивание и трей.
- Длинные списки, крупные редакторы правил, масштаб Windows и размер шрифта.

Сравнивайте одинаковые настройки, оборудование и release-сборки. Указывайте хеш EXE, число повторений, состояние подключения и отдельно учитывайте ядро. Числа рабочего набора не являются гарантией расхода памяти.

## Проверка ускорения 15 октября 2026

Изолированный Windows-контроллер, публичный тестовый профиль, без подключения VPN. До изменений выполнены три запуска; после — два запуска финальной сборки без фоновой компиляции. Кэш ОС не очищался. SHA-256 исходного EXE начинается с `C3911F95`, финального — с `A3970A14`.

| Измерение | До | После |
| --- | ---: | ---: |
| Первый список профилей | 5,86–7,94 с | 0,21–0,82 с |
| Полная готовность контроллера | 5,86–7,94 с | 5,32–5,56 с |
| Проекция 15 000 дополнительных доменных и процессных правил | 9,19–10,19 с | 0,34–1,14 с |
| Повторная проекция того же набора | 9,19–10,19 с | 0,13–0,24 с |

В финальных 20 измерениях медиана полного Status — 0,93 мс, условного Status — 0,97 мс; Rename — 59,89 мс, Autoconnect — 64,78 мс. Это время IPC без разбора JSON измеряющим скриптом. Применение отдельного набора из 15 000 доменных/IP-правил вместе с проверкой конфигурации ядром заняло 4,02 с. Эти два набора правил различаются.

Один восьмисекундный проход с открытым стандартным окном Slint и подтверждённым отключённым состоянием показал 968,75 → 843,75 мс CPU, то есть 12,10 → 10,52% одного логического ядра. Это предварительное измерение нагрузки анимации, а не проверка FPS или результат для всех устройств. Время реального VPN-подключения зависит от сервера и сети и этим набором испытаний не измерялось.

## Дополнительный эксперимент: предварительная компиляция помощников

После основной оптимизации проверена предварительная сборка трёх уже используемых C#-помощников (проверка файлов, JSON профилей и нормализация правил) в одну DLL. Эксперимент выполнен в отдельных копиях пакета с одинаковым EXE и публичными настройками; установленное приложение не изменялось.

По шесть запусков реального контроллера для каждого варианта, со сменой порядка сравнения: медиана полной готовности — 5,37 с без DLL и 4,79 с с DLL (около 11%). Диапазоны — 4,56–7,13 с и 4,17–7,46 с соответственно. Каждый запуск использовал новый процесс и отдельное состояние; кэш ОС не очищался. Во всех 12 запусках прошли проверки статуса, переименования и сохранения параметра автоподключения. Реальное VPN-подключение не выполнялось.

Решение: не включать эксперимент в продукт. Выигрыш ограничен и относится к инициализации службы; заметного ускорения обычных действий он не подтверждает. Дополнительный двоичный компонент и этап сборки пока не оправданы. Полный перенос управления из PowerShell в Rust также не начинается без измерения реального подключения по этапам и подтверждения существенной пользы.

## Проверки в репозитории

Ускорение запуска отделяет появление профилей от готовности сетевого контроллера. Постоянный помощник убирает повторную загрузку PowerShell-модулей; кэши настроек и проекции исключают повторную обработку неизменившихся правил. Проверки доступности двух адресов выполняются параллельно отдельно до и после включения TUN. Отмена фонового DNS освобождает очередь пользовательских операций.

В интерфейсе неизменившийся Status не копирует черновик и не обновляет модели. Сохранение оформления выполняется в отдельном потоке с объединением очереди, атомарной записью и сообщением об ошибке. Палитры текстур переиспользуются; UI и программный renderer собираются с оптимизацией скорости. Временное уведомление о связи удаляется после восстановления; успешные уведомления закрываются автоматически.

`tests/Test-Performance.ps1` проверяет совпадение нормализации и сортировки, инвалидирование и восстановление кэшей, отсутствие разделяемых изменяемых данных, постоянный UTF-8 обмен и параллельные HTTP-проверки на локальном сервере. Rust-тест дополнительно проверяет быструю отмену DNS с сохранением процесса основного помощника.

`tests/Measure-NativeControl.ps1 -Executable <release-exe> -VerifyNative -Output <json>` отдельно измеряет первое появление профилей, полную готовность контроллера и IPC на изолированных данных. Этот тест не измеряет Slint или сетевую задержку.

Preview в `ui/src/preview.rs` проверяет геометрию и взаимодействия на синтетических данных; это не измерение экранного FPS. `tests/Test-SlintStartup.ps1` проверяет реальный запуск и жизненный цикл окна.
