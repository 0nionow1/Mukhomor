# Режим Tor в Mukhomor

Предварительная версия: **0.8.8**. Сборка и сетевые испытания фиксируются отдельно;
наличие этого файла не означает опубликованный выпуск или независимый аудит.

Во вкладке **P2P** сеть **Tor** выбирается строкой, как профиль VPS. Она подключает
к бесплатной публичной сети Tor через официальный
Arti 0.47.0. Профиль VPS, регистрация, подписка и собственный выходной узел не
нужны. Приложение работает только как клиент, не становится ретранслятором или
выходным узлом. Собственная сеть Mukhomor отложена на более поздний этап.

## Поведение

### Подключение из сетей с DPI

В настройках доступны два готовых пресета: **Snowflake · CDN77** и
**Snowflake · AMP**. Адреса и аккаунт не нужны. AMP использует альтернативный
способ обращения к брокеру, опубликованный командой Tor Project; он всё ещё
зависит от WebRTC/UDP и не гарантирует обход блокировки этого протокола.
Для AMP ожидание загрузки увеличено до семи минут, затем проверяется сам туннель;
интерфейс предупреждает, что подключение может занять до восьми минут.
При отказе одного пресета можно явно выбрать другой. Автоматического перехода
на прямой Tor или обычный интернет нет.

Если настройки ещё не сохранены, выбран Snowflake CDN77. Обновление сохраняет
прежний выбор: для перехода с прямого Tor откройте настройки и выберите пресет.

Для **obfs4 / WebTunnel** нужны свежие строки мостов, а не профиль VPS.
Кнопки в приложении открывают [сайт Tor Project](https://bridges.torproject.org/)
и [официального бота @GetBridgesBot](https://t.me/GetBridgesBot). На сайте
выберите тип и решите капчу; боту отправьте `/obfs4` или `/webtunnel`.
Скопируйте строки в настройки выбранного транспорта и сохраните.
Аккаунт Tor и оплата не требуются. Для канала Telegram нужен свой Telegram;
можно воспользоваться сайтом без него. Mukhomor не отправляет сообщения боту.
Общий статический список частных мостов не встроен: такие адреса могут быстро
заблокировать. Получение мостов через Moat внутри Mukhomor пока не реализовано.

Служебные имена мостов и I2P получают адреса по HTTPS через Cloudflare;
при отказе используется Google Public DNS. Рабочий резолвер запоминается на
время процесса. TLS проверяется, редиректы и системный DNS запрещены;
ответ должен соответствовать запросу и содержать публичный адрес.
Это только DNS инфраструктуры: DNS пользовательских сайтов остаётся в Tor/I2P.

Проверка с VPS доказывает доступность с VPS, а не обход ТСПУ у пользователя.
Совместная работа двух системных VPN на Windows отдельно не квалифицирована;
обнаруженный конфликт не устраняется отключением защиты или чужого VPN.

Проверка 2026-10-17 из текущей физической сети Windows (отдельные тестовые
клиенты, без изменения маршрутов и Amnezia): Snowflake CDN77 — 41 с,
Snowflake AMP — 298 с до подтверждённого HTTPS-ответа `IsTor: true`.
На отдельном VPS: прямой Tor — 9 с, CDN77 — 67 с, AMP — 40 с.
Это результаты отдельных попыток, не гарантия времени или доступности.
Полный Windows TUN/WFP одновременно с Amnezia в этих проверках не запускался.

### Трафик и ограничения

- Tor передаёт TCP. UDP, QUIC, игры и звонки, требующие UDP, блокируются.
  Браузер может перейти с QUIC на HTTPS поверх TCP; это зависит от браузера.
- HTTP сохранён для совместимости по выбору владельца. Перед подключением
  интерфейс предупреждает, что выходной узел видит HTTP; используйте HTTPS.
- Перехваченный TUN-трафик идёт через Tor независимо от сохранённых исключений
  приложений, доменов и локальной сети. Настройки обычного VPS сохраняются.
- DNS приложений перехватывается TUN. DoH к двум адресам резолверов также идёт
  через Tor; системный DNS не служит запасным путём.
- Первая загрузка каталога и построение цепочки могут занимать до шести минут.
  Если сеть блокирует прямое подключение к Tor, подключение завершится ошибкой.
  В настройках Tor доступны прямое подключение, obfs4, WebTunnel и Snowflake.
  obfs4/WebTunnel требуют актуальных строк мостов с bridges.torproject.org;
  Snowflake использует опубликованную Tor Project конфигурацию автоматически.
  При выборе мостов нет скрытого перехода на прямые ретрансляторы.
- Между Mihomo и Arti используется только loopback SOCKS5 со случайными
  учётными данными на каждую сессию. Неавторизованные подключения и SOCKS
  UDP ASSOCIATE отклоняются. Процесс Arti завершается при закрытии stdin
  контроллера; цели соединений и пароли не выводятся в журнал.
- Для каждого SOCKS-соединения используется изолированный клиент Arti.
  Это не даёт браузеру защиты от отпечатка, которую предоставляет Tor Browser.
- Встроенное автоподключение VPS выключается при выборе Tor, чтобы восстановление
  приложения не подменяло сеть. Android Always-on восстанавливает последний тип
  сети по системному запросу.

## Платформы и отказы

**Windows.** До загрузки Tor устанавливается постоянная политика WFP. Внешние
TCP-соединения разрешены только установленному `mukhomor-tor.exe` от SYSTEM
при прямом подключении или `mukhomor-pt.exe` при использовании мостов.
Только для Snowflake последний также получает UDP для WebRTC/STUN; остальные
приложения такого разрешения не получают. Физические DNS 53/853 закрыты.
Транспорты привязывают сокеты к
физическому интерфейсу через IP_UNICAST_IF / IPV6_UNICAST_IF; сбой привязки не
приводит к попытке без неё. При остановке транспорта политика сохраняется;
явное отключение восстанавливает DNS, останавливает процессы и снимает защиту.
Живой TUN и разрешающие фильтры проверяются отдельно.
Windows может назначить ближайший свободный приоритет WFP и добавить флаг
индексации фильтров. Эти служебные изменения учитываются при чтении; идентичность,
ACL, условия и действия правил проверяются строго. Более приоритетное стороннее
неперекрываемое разрешение на слоях защиты вызывает явный отказ. Это относится
и к вызываемым драйверам (terminating/unknown callout), чьё решение нельзя
подтвердить по сохранённым флагам фильтра. Конфликтующий VPN нужно отключить.
Приложение не удаляет чужие правила. Явное отключение Mukhomor
доступно и при таком конфликте.

**Linux.** До загрузки Tor контроллер атомарно устанавливает таблицу nftables
с запретом внешнего трафика. Разрешены loopback, TUN, минимальные DHCP/NDP и
помеченные TCP-сокеты транспорта и отдельная UDP-метка Snowflake;
физические DNS 53/853 не разрешаются даже с меткой.
Arti задаёт SO_MARK и SO_BINDTODEVICE, без повторной попытки при ошибке.
Нужны nftables в ядре и Linux 5.17+ для SO_MARK с `cap_net_raw`; контроллеру
установщик выдаёт `cap_net_admin`. Таблица сохраняется после остановки Arti,
контроллера или GUI и обнаруживается при повторном открытии приложения.
Снять её можно явным отключением; удаление программы при оставшейся защите
отклоняется, чтобы сохранить возможность восстановления. Политика действует
для текущего сетевого пространства всей системы. Перезагрузка ОС, изменение
firewall администратором и привилегированный/raw-L2 обход не покрываются.

**Android.** Используется один VpnService и один TUN. Сохранённые исключения
других приложений в режиме Tor не применяются. Собственный UID Mukhomor исключён
для доступа Arti к ретрансляторам; в него входят служебные запросы приложения,
например проверка обновлений. При ошибке загрузки Tor созданный TUN удерживается
до явного отключения. Для блокировки после аварии всего процесса или перезагрузки
пользователь должен включить Android Always-on и «Блокировать соединения без VPN».
Без этой настройки ОС нельзя гарантировать блокировку после остановки VpnService.

Tor не делает произвольное приложение анонимным: аккаунты, отпечатки и передаваемые
самим приложением идентификаторы остаются. HTTP без TLS доступен выходному узлу.
Поддержка onion services в этой сборке отдельно не заявляется и не проверена.
Выходные узлы принадлежат третьим лицам. Выбор узлов и проверка подписанного
каталога поручены Arti; это не гарантия добросовестности выхода. Не отключайте
проверку TLS-сертификатов. Для веб-анонимности используйте Tor Browser.

## Мосты и границы защиты

`mukhomor-pt` использует закреплённые библиотеки Lyrebird 0.9.0, obfs4,
WebTunnel и Snowflake 2.14.1. Это клиент, без режима добровольного прокси.
Локальные прокси требуют случайный секрет: пользовательский SOCKS меняет его
каждую сессию, а внутренний PT сохраняет в приватном состоянии Tor. Это нужно
для стабильной идентичности моста в Arti после перезапуска. У каждого набора
мостов отдельное состояние; возврат к набору сохраняет его прежний выбор узлов.
Закрытие Arti завершает PT,
закрытие PT завершает Arti; блокировка сети остаётся до явного отключения.
Строки мостов ограничены по длине, числу и допустимым параметрам; пользователь
не может задать исполняемый файл или командную строку транспорта.

Для служебных имён WebTunnel/Snowflake применяется HTTPS DNS через Cloudflare
на 1.1.1.1:443 с проверкой сертификата и привязкой к физическому интерфейсу.
Эти служебные запросы выполняются до Tor; DNS пользовательского трафика идёт
внутри Tor. При недоступности служебного DoH системный DNS не используется.
Служебный резолвер пока требует IPv4. Snowflake требует доступного UDP до
добровольцев/STUN. Мосты не гарантируют обход любой блокировки.

Arti 0.47.0 ограничивает всё рукопожатие PT десятью секундами. В локальной
проверке Snowflake понадобилось 37 секунд. `tor/prepare.py` воспроизводимо
увеличивает только этот лимит до 90 секунд в проверенном по SHA-256 исходнике;
проверка идентичности Tor и криптография не изменяются. `pt/prepare.py`
подключает к Snowflake привязанные сокеты и служебный DoH; кеши зон IPv6 Android
оставлены локальными, без доступа к внутренним структурам Go.
Также исправлен бесконечный поиск пределов SystemTime в saturating-time 0.5.0:
шаг меньше точности часов Windows не меняет время и теперь считается
отсутствием прогресса. Это устраняет зависание после рукопожатия Tor;
проверка пределов системного времени ограничена двухсекундным тестом.
Оригиналы зависимостей
в source-архивах сохраняются без изменений; кеши компиляторов не редактируются.

## Следующие сети

Следующий этап ограничен бесплатными вариантами. Наличие бесплатного клиента
не означает бесплатный, доступный и проверенный выход в обычный интернет.

Nym, Mysterium, Lokinet, I2P и Yggdrasil требуют отдельных адаптеров и испытаний;
в этой сборке они ещё не доступны. Nym и Mysterium могут требовать оплаты,
Lokinet — настройки выхода. I2P ориентирована на собственные сервисы, а Yggdrasil
даёт зашифрованную IPv6-сеть без обещания анонимности. Их нельзя обозначать
в интерфейсе как равноценные проверенные способы выхода в интернет.

## Проверка 0.8.6

Проверка 16 октября 2026 года:

- Штатный Windows-процесс Arti с Snowflake выполнил HTTPS-запрос к
  `check.torproject.org/api/ip`; сертификат проверен, ответ подтвердил `IsTor`.
  Окончательный бинарник выпуска прошёл первое соединение примерно за 45 секунд
  и повторное с тем же состоянием примерно за 100 секунд. Принудительное
  завершение PT после HTTPS завершило Arti и закрыло SOCKS-порт. Это отдельный клиентский
  процесс без изменения маршрутов хоста, а не испытание установленного VPN.
- Исправлены смена идентичности моста после перезапуска, зависание часов Windows,
  преждевременное завершение PT при сборке
  мусора и остановка локального слушателя после некорректного SOCKS-запроса.
  Регрессионные тесты времени, аутентификации, EOF и запрета UDP прошли.
- Реальный Windows BFE проверил политики прямого Tor, TCP-мостов и Snowflake
  в откатываемой транзакции от SYSTEM. Действующие фильтры не изменялись.
- В изолированном Linux network namespace прошли проверки TUN, TCP, IPv4/IPv6,
  DNS 53/853, запрета пользовательского UDP, разрешения только помеченного
  служебного UDP, отказов, SIGKILL и явного восстановления сети.
- После обновления `x/net`, Pion DTLS и STUN `govulncheck` не нашёл достижимых
  уязвимых символов в PT. Это результат проверки известных проблем зависимостей,
  а не доказательство отсутствия всех уязвимостей.
- Проверены P2P и диалог мостов на экране 360×640. Конфигурация Tor принята
  реальным Mihomo; сценарии PowerShell не меняли сеть хоста.
- Подписанный release APK 0.8.6 испытан на изолированном Android 15 x86_64:
  во время загрузки Snowflake и после SIGKILL PT сохраняется TUN, контрольный
  TCP от UID shell не проходит, Arti завершается. Явное отключение удаляет TUN
  и восстанавливает контрольное соединение. Это проверка отказа, без подтверждения
  публичного Tor-выхода на Android и без испытания аварии всего приложения.

Повторные подключения Snowflake зависят от доступности добровольных прокси;
отдельные попытки в этой сети завершались тайм-аутом. Публичные подключения
через obfs4 и WebTunnel ещё не проверены с рабочими мостами. Новые мосты на
Android ещё не испытаны на физическом устройстве; проверка ARM64 ограничена
сборкой. Полное Windows-подключение с WFP и действующим сторонним VPN пока
не испытывалось: установленное приложение и Amnezia не изменялись.

## Проверка безопасности 0.8.5

Проверка 16 октября 2026 года — анализ исходников, тесты и локальные сетевые
испытания; это не независимая сертификация безопасности сети Tor.

- В изолированном Linux network namespace проверены реальные TUN и nftables:
  TCP через тестовый SOCKS, запрет физического IPv4/IPv6 TCP, UDP и DNS,
  включая помеченные TCP 53/853; отказ загрузки, SIGKILL транспорта и всего
  контроллера, восстановление сохранённой защиты и явное отключение.
  Отдельно прошла регрессия обычного VPN с TCP, UDP, DNS и исключениями.
- Go race-тесты, тесты Rust транспорта и нативного приложения прошли.
  Windows-сценарии отказа конфигурации и жизненного цикла WFP проверены
  с подменой системных вызовов; это не испытание фильтров на реальном хосте.
- После воспроизведения `WFP_SUBLAYER_MISMATCH` выполнен дополнительный тест
  реального Windows BFE от SYSTEM: создание полной политики, проверка всех
  объектов, распознавание стороннего неперекрываемого разрешения, удаление
  только собственных объектов и откат транзакции. Windows вернула приоритет
  65532 вместо запрошенного 65535 и добавила `INDEXED`; оба допустимых изменения
  теперь учитываются. Тест не фиксирует транзакцию и не меняет текущий трафик;
  он не заменяет испытание подключённого Tor с захватом пакетов.
- В Windows PowerShell 5.1 отдельно проверен настоящий тестовый дочерний
  процесс: UTF-8 без BOM, Unicode-пути, отмена загрузки, некорректные ответы,
  ошибка создания процесса и завершение по EOF. Не используется отсутствующее
  в .NET Framework свойство `StandardInputEncoding`. Этот тест проверяет
  обмен с процессом, а не доступность публичной сети Tor. Технические сообщения
  Tor передаются на английском; русский перевод применяется только в GUI.
- На эмуляторе Android 15 APK 0.8.5 сохраняет TUN во время загрузки и после
  принудительного завершения Arti. Контрольный TCP от UID shell блокируется;
  явное отключение удаляет TUN и восстанавливает тот же TCP. Авария всего
  приложения с системным Always-on/lockdown отдельно не испытывалась.
- Прямой пробный запуск Arti в доступной сети не завершил загрузку за 310 секунд.
  Успешный выход в публичный Tor и проверка `IsTor` пока не подтверждены.
  Синтетический SOCKS в Linux-тесте не проверяет криптографию и доступность Tor.
- Для 897 пар имени/версии из Cargo.lock выполнена проверка OSV. Обнаружены
  предупреждения о прекращении сопровождения `bincode 2.0.1`, `paste 1.0.15`,
  `ttf-parser 0.25.1`, а также [RUSTSEC-2023-0071](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)
  у `rsa 0.9.10`, для которого нет исправленной версии. В используемом пути
  Arti найдена проверка RSA-подписей; сетевой путь расшифровки RSA с закрытым
  ключом не обнаружен. Это ограничивает применимость найденной проблемы,
  но не заменяет последующий аудит при обновлении Arti.
- `govulncheck` для Linux Go-контроллера не обнаружил достижимых уязвимых
  символов. Предупреждение `GO-2026-5932` относится к неиспользуемому OpenPGP
  в модуле `x/crypto`. Наличие зависимостей в lock-файле само по себе не
  доказывает ни эксплуатацию, ни отсутствие риска.

## Приёмка

Сборка из Git автоматически создаёт отсутствующий `Source/tor-dependencies.zip`
из закреплённых пакетов Cargo и проверяет его SHA-256. Отдельная команда:
`python tor/licenses.py --source-only`; для заполненного кеша добавьте `--offline`.
Для Windows из Git нужен Python, путь передаётся в `Build-All.ps1 -Python` или
`Build-Release.ps1 -Python`. Обновление лицензий и пинов выполняется отдельным
запуском `python tor/licenses.py` после проверки изменений зависимостей.

1. Проверить конфигурацию реальным Mihomo на каждой платформе: отсутствие DIRECT,
   отказ UDP, все пути DNS через Tor и сохранение обычных настроек.
2. Проверить SOCKS-аутентификацию, отказ UDP ASSOCIATE, тайм-аут и отмену загрузки.
3. Проверить TCP через Tor с подтверждением `IsTor` и захватом пакетов на физическом
   интерфейсе; отдельно проверить IPv4/IPv6, DNS, UDP и исключения приложений.
4. Завершить Arti и контроллер по отдельности; проверить фактическую блокировку,
   отображение отказа и явное отключение. Windows — также перезапуск службы;
   Android — отзыв разрешения и Always-on/lockdown; Linux — сохранение nftables
   после SIGKILL, обнаружение защиты после перезапуска и явное отключение.
5. Проверить APK на устройстве, обновление всех четырёх бинарников Linux и полный
   Windows-пакет. Успешная компиляция не заменяет пункты 3–4.
