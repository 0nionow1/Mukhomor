# Mukhomor 0.8.1: Windows, Linux и Android

Windows, Linux и Android — обязательные платформы проекта. Версия исходников
0.8.1. Опубликованные файлы и статус проверки указаны в [GitHub Releases](https://github.com/0nionow1/Mukhomor/releases/tag/v0.8.1).
Новые платформы используют тот же Slint-интерфейс, темы, редактор правил и
наборов. Windows сохраняет свой установленный контроллер и существующие профили.

## Сборка всех платформ и расположение файлов

Из полного checkout на Windows с настроенным WSL:

```powershell
./Build-All.ps1 -DebugAndroid
# Для собственного ядра добавьте -Mycelia.
# Для релизного APK вместо -DebugAndroid передайте -Keystore и -KeyAlias.
```

Скрипт собирает Windows x64, Android ARM64/x86_64 и Linux в WSL. Для нестандартного
расположения Linux-инструментов можно передать `-LinuxEnvironment` с PATH и
путями кешей. Android использует те же SDK/JDK-параметры, что `Build-Android.ps1`.
Ошибка любой платформы означает неуспешную общую сборку.

```text
release-staging/
  0.8.1/
    windows/x64/                  ZIP, исходники, SHA-256, package/Mukhomor
    linux/x64/                    tar.gz и SHA-256 (исходники внутри)
    android/universal/debug/      тестовый APK, исходники, SHA-256
    android/universal/release/    релизный APK, исходники, SHA-256
```

Для отдельного Android ABI вместо `universal` используется `arm64-v8a` или `x86_64`;
для Linux ARM64 — `linux/arm64`. Повторная успешная сборка заменяет файлы в том же
каталоге. Временные Windows/Android-файлы находятся в `target/`, Linux — в системном
временном каталоге. Старые версии хранятся отдельно; `dist/` больше не используется.
Небольшие правки сохраняют версию, средние и крупные повышают последний номер.

## Подготовка при запуске

Стартовый экран использует тот же рисунок и анимацию, что кнопка подключения.
В это время рабочий поток открывает контроллер: Linux запускает дочерний процесс,
Android инициализирует JNI-контроллер, Windows получает состояние своей службы.
Контроллер читает приватную библиотеку, загружает настройки/правила и возвращает
фактическое состояние VPN. Предварительные метаданные с `initializing=true` не
завершают подготовку. Только готовый ответ открывает главный экран; анимация
не подключает VPN и не задерживает быстрый запуск ради длительности заставки.
Уже настроенное автоподключение работает по прежним правилам.

Ошибки и длительное ожидание показывают повторную проверку и возможность открыть
приложение для восстановления. Сбой последующего опроса не возвращает заставку.
Отключённая анимация сохраняет статичный экран с тем же реальным условием готовности.

## Linux

Сборка рассчитана на 64-битный Linux с glibc и графической сессией X11 или Wayland.
Окружение проверки — Ubuntu 24.04 в WSL2 с WSLg. Сборку для другой архитектуры
нужно выполнять на соответствующей машине; имя пакета включает `x64` или `arm64`.

Для сборки нужны Python 3, Rust stable, Go 1.27.2, C/C++-компилятор, CMake, pkg-config,
заголовки fontconfig, xkbcommon, Wayland, OpenSSL и XCB. Для выбора файлов нужен
`zenity`; для установки — `setcap` из `libcap2-bin`/`libcap`.

```sh
bash Build-Linux.sh
tar -xzf release-staging/0.8.1/linux/x64/Mukhomor-0.8.1-linux-x64.tar.gz
cd Mukhomor-0.8.1
sudo bash install.sh
mukhomor
```

Интерфейс работает от обычного пользователя. Только установленный контроллер
получает `CAP_NET_ADMIN` для создания TUN и временных маршрутов. Приложение не
перезаписывает `/etc/resolv.conf`: DNS перенаправляется внутри TUN. При отключении
ядро закрывает туннель и убирает свои маршруты.

Профили хранятся в `$XDG_DATA_HOME/mukhomor`, по умолчанию
`~/.local/share/mukhomor`. Каталог имеет права 0700, файл библиотеки — 0600.
Обновление приложения сохраняет данные. `sudo bash uninstall.sh` удаляет
исполняемые файлы и ярлык, сохраняя пользовательские профили.

Настройка запуска при входе создаёт пользовательский XDG-autostart ярлык.
Автоподключение включается отдельно и использует последний успешно подключённый
сервер. На рабочем столе без системного трея закрытие окна завершает VPN;
при наличии трея окно можно скрыть и управлять подключением из меню.

## Android

Android 8.0 (API 26) и новее. Сборщик создаёт APK для ARM64 и x86_64; ARM64
предназначен для современных телефонов, x86_64 также используется эмуляторами.
Установка не требует root. Подключение требует стандартного разрешения Android
на VPN, а фоновая служба показывает постоянное уведомление с отключением.

Для локальной сборки в Windows нужны Android SDK 35, Build Tools 35.0.0,
NDK 27.2.12479018, JDK 17, Python 3, Go 1.27.2 и Rust с Android-targets:

```powershell
rustup target add aarch64-linux-android x86_64-linux-android
./Build-Android.ps1 -DebugBuild
adb install -r release-staging/0.8.1/android/universal/debug/Mukhomor-0.8.1-android-debug.apk
```

Сборщик использует `ANDROID_HOME`, `ANDROID_NDK_HOME`, `JAVA_HOME` и `go` из PATH;
их можно передать параметрами `-Sdk`, `-Ndk`, `-Java` и `-Go`. Тестовый APK
подписывается отдельным локальным отладочным ключом. Выпуск требует `-Keystore`,
`-KeyAlias` и переменной `MUKHOMOR_KEYSTORE_PASSWORD`. Ключи и пароли не входят
в исходники или пакет. Для обновлений нужен тот же ключ подписи.

Начиная с Android 12, системная заставка использует AnimatedVectorDrawable из
общего рисунка `native/src/mushroom.rs` и цветов `assets/theme.json`. Сборщик
генерирует ресурс через `android/Generate-LaunchArtwork.py` в `target/`.
Заставка плавно исчезает после первого кадра приложения; дополнительной задержки
для проигрывания анимации нет. На Android 8–11 системный экран статичный,
затем работает общий анимированный экран подготовки Slint.

Файлы импортируются через системный выбор документов. Приложению не нужен доступ
ко всему хранилищу. Профили сохраняются только во внутреннем каталоге приложения;
резервное копирование Android для него отключено. Закрытие экрана приложения
сохраняет VPN; кнопка отключения и отзыв VPN-разрешения закрывают TUN.

Для исключения Android-приложения в списке имён процессов укажите его package ID,
например `org.example.game`. Windows-имена `.exe` сохраняются в общих наборах,
но не превращаются в исключения Android. Полный режим игнорирует исключения
приложений. Постоянный VPN и системную блокировку соединений без VPN включают в
настройках Android. Обычный полный режим маршрутизации сам по себе не является
обещанием блокировки трафика после остановки приложения.

## Общий контроллер

`core/` реализует ограниченный импорт отдельных серверов, атомарное хранение,
шесть типов правил, объединение наборов, обновление доменных списков и управление
mihomo v1.19.32. `cmd/mukhomor-controller` обслуживает Linux по приватным каналам
stdin/stdout. `cmd/mukhomor-android` собирается в библиотеку JNI для VpnService.
Публичного HTTP API и открытого локального прокси-порта у них нет.

Управление Windows остаётся в `native/src/backend.rs` и PowerShell-модулях.
Профили Windows не переносятся в Android или Linux автоматически. Экспериментальное
ядро Mycelia включается параметром `-Mycelia` Android-сборщика или
`MUKHOMOR_MYCELIA=1 bash Build-Linux.sh`. Нужен проверенный архив
`Source/mihomo-mycelium-source.zip` и соответствующий `mycelium-build.json`
в `Source/` либо `bin/`. Сборщик проверяет контрольную сумму; стандартное ядро
не подменяет отсутствующий протокол другим. `Prepare-PortableCore.py` сохраняет
отдельный модуль и исходники в `target/`, не меняет глобальный Go-кеш и вносит
явную передачу владения Android-дескриптором TUN. Публикуйте соответствующие
исходники и лицензии вместе с каждым бинарным выпуском.
Android-сборщик создаёт рядом с APK архив `*-android-source.zip` и SHA-256.
Linux-пакет содержит такой архив в `Source/Mukhomor-source.zip`.
В них входят только явно перечисленные публичные файлы, точный снимок ядра
и манифест контрольных сумм; профили, локальные ключи подписи и кеши исключены.

## Проверка

```sh
go test -tags=with_gvisor ./core ./cmd/mukhomor-controller
cargo test --manifest-path ui/Cargo.toml --locked --lib
cargo test --manifest-path native/Cargo.toml --locked --lib -- --test-threads=1
go build -tags=with_gvisor -o /tmp/mukhomor-controller ./cmd/mukhomor-controller
sudo python3 tests/linux-network.py /tmp/mukhomor-controller
```

Последняя команда создаёт две временные сетевые области Linux. В них проверяются
настоящие TCP/UDP через TUN, DNS/fake-IP, прямые исключения и повторное отключение
с очисткой маршрутов. Основная сеть компьютера и существующий VPN не изменяются.
Для Android отдельно нужны установка APK, системное подтверждение VPN,
проверка фоновой работы, отзыва разрешения, импорта и смены сети на устройстве.
Результаты компиляции, модульных проверок и реальных сетевых испытаний учитываются
отдельно; успешная сборка не заменяет испытание VPN.

### Проверено при подготовке 0.8.0 (15 октября 2026)

| Среда | Проверка |
| --- | --- |
| Windows x64 | Компиляция общего Slint-хоста, тесты команд, сохранения/отмены правил и полноты переводов |
| Ubuntu 24.04, WSL2 | Установка от root, интерфейс от обычного пользователя, X11, активация существующего окна, закрытие без трея; тот же бинарник отрисовывает окно через Wayland |
| Linux, изолированные network namespaces | TCP/UDP через настоящий TUN, DNS/fake-IP, прямые CIDR-исключения, передача данных после одинакового повторного подключения, очистка маршрутов; контроллер с UID 1000 и только CAP_NET_ADMIN |
| Android 15, x86_64 эмулятор | Импорт документа через SAF, отказ в разрешении, TCP/UDP IPv4 и IPv6 через VPN, DNS/fake-IP, повторное подключение, работа в фоне, переключение Wi-Fi, отключение уведомлением и отзыв разрешения; постоянный VPN восстанавливает трафик после перезагрузки без открытия приложения |
| HONOR ABR-LX1, Android 15, ARM64 | Установка, запуск и главный экран; подтверждено владельцем устройства |

В WSL Slint по умолчанию выбирает X11. Wayland проверен отдельно в приватном
mount namespace без признаков WSL, с обычным UID и тем же установленным бинарником.
Эмулятор использует `tests/android-fixture.py` на loopback хоста и
`tests/android-probe.c`, запущенный через ADB вне исключённого UID приложения.
Тестовые назначения не являются реальными VPN-серверами.
Отдельный тест принудительного `SIGKILL` процесса Android выявил ограничение API 35
эмулятора: система регистрирует `DeadObjectException` при отвязке VpnService и не
перезапускает службу, хотя она возвращает `START_STICKY`. Повторное включение
постоянного VPN в настройках восстанавливает службу и трафик; перезагрузка также
проверена. Автоматическое восстановление после такого завершения не подтверждено.
Управление постоянным VPN делегировано [системе Android](https://developer.android.com/develop/connectivity/vpn#always-on);
собственного обходного фонового планировщика приложение не запускает.
Минимальная версия Android в манифесте — API 26; устройства API 26–34, страницы
памяти 16 KiB и Linux ARM64 отдельно на оборудовании не проверялись. Это не
заявление о длительной сертификации всех прошивок, дистрибутивов и протоколов.

## Подписание выпуска

CI собирает тестовый Android APK. Workflow выпуска требует секреты
`MUKHOMOR_ANDROID_KEYSTORE_BASE64`, `MUKHOMOR_KEYSTORE_PASSWORD` и
`MUKHOMOR_ANDROID_KEY_ALIAS` для постоянного ключа подписи. При их отсутствии
подготовка общего выпуска останавливается. Linux и Android собираются до
создания черновика; workflow не публикует его автоматически.
