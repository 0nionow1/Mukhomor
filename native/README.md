# Mukhomor native

Settings → Appearance offers 20 complete presets. Neon (pink/neon teal) is the default; Classic retains its original violet/teal palette. Reactor, Cyberpunk, Biopunk, Plasma, Voltage, Toxic, Mint Fire, Ultraviolet, Laser, Rave Sunset, Cherry Ice, Deep Dive, Orchid, Arcade, Acid, Hologram, Dragon and the light Pop Art preset use vivid contrasting accent pairs. The gallery shows both accents and scrolls with the catalog size. Existing saved theme IDs remain valid. Every preset defines surfaces, primary-button ink, active/disabled states, error colors and texture palettes. Theme switching rebuilds only native paint resources, retaining the indexed animation field and phase. All presets use compact logo 04 and its detailed mycelium button: the cap follows the primary accent, the spots follow the secondary accent, and the stem stays neutral. Window and tray icons follow the current theme; the executable resource uses Neon. The shared artwork and icon rasterizer live in `src/mushroom.rs`.

Small (85%), Medium (100%, default) and Large (125%) scale the entire client: fonts, icons, artwork, controls, padding, hit areas, menus and scrollbars. The user scale composes with the current monitor DPI; the window stays within the monitor width, uses compact layouts and scrolls on short work areas. Changes apply immediately. Reset appearance restores the visual defaults without touching language, VPN state or rule drafts.

Stable `design.theme` and `design.interface_size` identifiers live in the per-user `ui-preferences.json`, with atomic writes shared with language/effect settings. Missing or invalid values fall back to Neon/Medium. `appearance.rs` owns the palette and size data; `appearance_ui.rs` owns the native settings controls and focused QA. `--smoke --smoke-render-only` covers all 60 combinations, 100/125/150/200% monitor DPI, short windows, resource reuse and draft/caret preservation. `--smoke --smoke-appearance-only` can additionally start against an isolated preferences fixture to verify restart behavior. Neither mode connects a VPN.

The controller handles `Rename` and `Autoconnect` as serialized Rust metadata transactions after successful initialization. Each transaction pins and checks the state directories and profile index, bounds and validates the library, and atomically replaces it before updating the public snapshot. Activation, import, settings validation and network recovery continue through the supervised bridge. Uncertain initialization uses the existing bridge path.

`Status` accepts an optional `if_revision` token. Matching snapshots return only `ok`, `not_modified` and `revision`; callers without a token retain the full response. Every mutable cache access invalidates the token, and controller lifetimes have distinct tokens. The UI clears its token on mutation admission, replies and transport failures, preserves drafts on compact replies, and refetches on mismatches.

Use `tests/Measure-NativeControl.ps1 -Executable <release-exe> -VerifyNative -MeasureStartup -Output <json>` for an isolated controller/GUI benchmark. It measures real IPC metadata operations, full/conditional status bytes, controller readiness, first window presentation and controls after the first confirmed snapshot. No VPN is connected. The QA UI mode requires `qa.marker` and closes its own window after recording; its timings exclude installation verification and use an already ready controller. Keep baseline and candidate builds under the same configuration; timing thresholds are not asserted on shared CI machines.

Settings application reuses the diagnostics from the rule projection used to build the core configuration. The diagnostics are published only after core validation and the settings transaction succeed; the stored settings retain the user's original entries. `tests/Test-NativeApp.ps1 -Executable <release-exe> -LargeRulesOnly` runs the 15,000-entry IPC regression separately and reports its elapsed time, including a check that empty diagnostics remain an empty JSON array.

Visual convention: all controls and status marks keep the pixel style. Checkmarks use exactly four large square blocks, with integer scaling and no font glyphs, thin diagonal strokes or antialiasing; the same drawing is used for settings, presets and the selected server.

Rendering stability: one published background frame covers the entire client area, including the header, caption buttons and bottom navigation. The active tab uses accent-colored text and icons; hover/focus adds an outline over the same background. Buttons and native inputs present reusable paint buffers without an intermediate background erase. Inputs explicitly paint stepped outlines while preserving native editing behavior. Partially clipped children sample the visible intersection of the current animation frame instead of falling back to a static texture. Ambient frames invalidate the parent and background-dependent controls; opaque fields and lists remain outside the animation paint loop. Parent painting clips its reusable buffer to the update rectangle. Animation pauses while another app is active, the window is being moved/resized, a text field is focused, or content is being scrolled, and resumes from the same phase. Layout batches sibling changes with DeferWindowPos and disables copying stale pixels. Scrolling clips full-height native controls at the header/footer instead of shrinking their text area or hiding partially visible rows. The main scrollbar is five logical pixels wide and remains confined to the content viewport; dragging preserves the grab offset. Refreshing a hidden list never sends WM_SETREDRAW(TRUE), which would make it visible.

Settings → Appearance includes a pixel-drawn native speed slider from 25% to 200% (default 100%). Dragging previews speed immediately; arrow keys move by 5%, Page Up/Down by 25%, and Home/End select the limits. Speed scales elapsed animation time without changing the 50 ms paint cadence or resetting the current phase. A completed gesture saves `design.animation_speed` in `ui-preferences.json`; a short idle timer also commits interrupted gestures. Older preferences default to 100%, and loaded values are bounded. Disabling animation or visual effects disables the slider while preserving its value. Focused smoke QA covers speed, keyboard controls, persistence and pause/resume.

The speed control reuses its own paint buffer. Offscreen QA captures request its `WM_PRINT` path explicitly over the composited window snapshot: `PrintWindow` can otherwise retain old trackbar pixels when the window is outside the desktop. The capture preserves the control's actual clipping region and checks its thumb pixels at all four DPI scales; it is not a measurement of on-screen frame pacing.

Run `mukhomor.exe --smoke --smoke-render-only --base <project> --root <isolated-output>` for focused rendering QA without a service or VPN connection. It checks hidden-list refreshes, animation suspension, unchanged opaque controls, background continuity through header/footer/navigation, partial rows, native stepped input frames, preserved editor text/caret, and the five-pixel content scrollbar at 100–200% DPI. It also includes the existing chrome, home, design and edit-buffer checks. The offscreen fixture forces full parent paints for its conservative frame measurement because Windows may discard partial offscreen damage. The full `--smoke` run includes these regressions as well.

Rust/Win32 event-driven GUI and local controller. Build from the project root with Build-Release.ps1. The compiled palette and mushroom icon come from assets/theme.json. Tiny5 Regular is embedded and registered privately for the GUI lifetime; see assets/fonts/README.md and Tiny5-LICENSE.txt in the project root. Pixel geometry and buffered GDI painting keep animation limited to the visible window. See ../README.md for setup, isolation and verification.

ProfileImport.psm1 normalizes local share links, base64 link lists, standalone JSON/YAML nodes, legacy WireGuard/AmneziaWG files and a strict inline OpenVPN subset. A batch is parsed and checked by the pinned core before the library changes. Library schema 1 retains legacy .conf entries; new entries use a private JSON envelope and expose only id/name/protocol over IPC. All protocols share the existing AWG proxy alias and split rules. Non-WireGuard endpoints retain their hostname for TLS/SNI/Reality and bind to the physical interface; endpoint A/AAAA addresses are excluded from TUN routes. The import form uses a native EDIT control, not a browser or clipboard poller. The title displays the compiled Cargo version.

build.rs bakes domain-warped Perlin noise into an 8-bit indexed field and 24 keyframes for a seamless 48-second lava flow. Neon uses dark plum with pink and teal shading; other presets remap the same field to their own accent pair, and Classic retains its original zinc/indigo ramp. The 13-pixel logical cells meet without grid lines. texture.rs caches five indexed surface DIBs and solid brushes through RAII. Animation uses integer palette interpolation only for visible coarse cells, then row copies into one reusable viewport DIB. The frame is prepared before invalidating the parent and transparent controls, so child-first painting uses the same phase. No runtime noise or trigonometry is calculated. The 50 ms timer stops when hidden or minimized; opaque editors and lists are excluded from animation invalidation. The explicit background animation preference is independent of Windows' native control animation setting. Tests verify visible motion within two seconds, bounded color changes between frames, gapless cells, seamless looping, clipping, DPI changes and stable GDI handles across 960 frames.

design.rs supplies symmetric, integer, three-step corners with up to four-pixel treads at 100% DPI, shallower steps on small controls, and a reusable region cache. Buttons, check marks, combo arrows, menus and rule diagnostics use the bundled pixel font and GDI block geometry. Settings → Appearance offers a master switch and separate animation and corner switches. Legacy grid preferences are ignored. The master switch removes textures, disables animation and releases the viewport bitmap while retaining the pixel font and icons. Preferences share the bounded, atomically replaced per-user ui-preferences.json with language and never enter the VPN settings draft. Smoke QA covers persistence, independent toggles, caret preservation and hidden/minimized animation suspension.

The top-level window uses WS_EX_COMPOSITED. Each ambient frame holds a window DC only across its synchronous parent/child paints, then releases it to publish the completed frame. RedrawWindow alone is not a presentation transaction: individual EndPaint calls can otherwise publish intermediate content. Parent invalidation explicitly uses RDW_NOCHILDREN; only controls that show the animated field receive separate invalidations. After painting scrolled content, the backbuffer viewport returns to the origin before BitBlt; otherwise the source coordinates apply the scroll offset a second time.

`--smoke --smoke-animation-only` records actual WM_PAINT/WM_ERASEBKGND messages across all four pages at 100/125/150/200% DPI in `native-animation-isolation.json`. It requires one parent paint and one paint per background-dependent control per frame, zero paints of opaque controls, zero erases, and no layout/geometry changes. Internal paints exercise the offscreen fixture without making it visible; checking only GetUpdateRect after a synchronous redraw would miss unnecessary paints that already finished. The same regression runs in the render-only and full smoke suites.

Native EDIT and LISTBOX controls share a buffered stepped frame, including the full server/preset list surface, unused rows and keyboard focus. List height is independent of whole-row rounding; selection and scroll remain native. The rule-owner dropdown also follows the corner preference when opened or resized. `--smoke --smoke-lists-only` verifies painted edges, square-mode restoration, focus, selection/scroll preservation, empty-state text and popup regions at 100–200% DPI. Rule insertion uses an undoable native edit and scrolls to the added line.

The controller reads one bounded UTF-8 JSON reply terminated by a newline from NativeBridge.ps1. A successful core remains a live descendant of the helper, so the reply boundary must not depend on stdout reaching EOF. Helper exit, cancellation and operation deadlines remain supervised separately. Windows documents the inherited-pipe behavior in [Pipe Handle Inheritance](https://learn.microsoft.com/en-us/windows/win32/ipc/pipe-handle-inheritance).

Fresh Connect, Select and Update actions clear a completed cancellation only while holding the connection-intent lock and matching its generation. A newer Disconnect or Exit retains priority, including during a queued selection or rule update. Test-Disconnect.ps1 -CancellationOnly exercises repeated cancel/select/reconnect cycles with isolated helpers.

Custom domain lists of 32 or more entries compile into Mihomo's native immutable domain set; exact entries and +.suffix entries preserve their original DIRECT priority. Custom IP lists of 32 or more entries use the native merged IPv4/IPv6 set with domain resolution retained. Inline payloads belong to the validated candidate, including rollback. Socket attribution is strict when EXE rules exist and off otherwise. ApplySettings validates once, and its response reuses the validated settings. Scalar-array copies retain empty/single/nested JSON array shapes without a per-item PowerShell pipeline. API probes parse only the controller settings. Test-LargeRules.ps1 and the maximum-list IPC regression cover this behavior; Measure-Routing.ps1 reports a loopback comparison with raw samples and explicit measurement limits.

The mushroom button paints into a reusable child buffer at a 33 ms cadence and presents one clipped BitBlt per frame. Its cap and stem retain the original broad pixel steps and flat edges, with one-pixel trims confined to the four bottom cap/foot corners; three slightly smaller rectangular spots with one-pixel corner trims sit a little higher and to the right on the cap and breathe independently in idle, connecting and connected states. Pending captions retain three accented hopping dots. Mycelium follows weighted paths with staggered forks, intermediate opacity and bright growing tips. Only service confirmation starts the 800 ms completion wave; pending growth never reaches the finished state. Disconnect retracts the branches over 700 ms. Reduced motion keeps static status artwork, and hidden/inactive windows suspend the timer. `--smoke --smoke-hero-only` checks growth, dots, resource reuse and reduced motion; add `--smoke-hero-frames` to capture actual native frames. Native edit controls retain their caret, selection and scrolling behavior. All padding is inside the client surface, so composition paints each field at once without stale nonclient strips. ES_WANTRETURN distinguishes multiline lists from compact fields; compact fields center visible Tiny5 glyphs, suppress line breaks and normalize pasted line breaks to spaces.

The Presets page owns creation, deletion, checkbox activation and bounded portable JSON import/export. The Rules page owns one editor for all six sections, with explicit Add/Remove actions and secondary metadata/source options. Legacy visibility flags no longer hide lists. DNS is a Settings subpage. Draft collection precedes owner/category changes. Native smoke covers the separate workflows, raw draft preservation, linked sources, transfer roundtrips and 100–200% DPI layout. Export whitelists preset fields and excludes identities and connection settings; import generates a new disabled identity. Backend normalization repairs only exact shipped mojibake descriptions identified by builtin_id.
